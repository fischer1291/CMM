# ADR 0001: Keine Übersetzung, Locale wird nur gemessen

**Status:** beschlossen (Oktober 2026, Plan-Punkt 1.11)

## Entscheidung

- In den nächsten 12 Monaten wird die App nicht übersetzt. Sie bleibt deutsch, nur iOS, nur DACH.
- Das Backend merkt sich je Nutzer die Sprache des Geräts aus dem `Accept-Language`-Header (`User.locale`, z. B. `de-DE`) und zählt `users.byLocale` im Tages-Snapshot. Das ist reine Messung; nichts in App oder Backend verhält sich je nach Locale anders.
- Neue nutzersichtbare Strings stehen ab jetzt in der Komponente oder dem Modul, das sie zeigt, nahe am Code (wie bisher). Keine i18n-Bibliothek, kein zentraler String-Katalog, keine Umstellung bestehender Strings.

## Warum

Jede Übersetzung kostet laufend (jeder neue String, jeder Push-Text, jede Mail, der Store-Eintrag, der Support) und bringt erst etwas, wenn es Nutzer gibt, die sie brauchen. Die gibt es heute nicht messbar. Erst messen, dann entscheiden.

## Revision

Diese Entscheidung wird neu getroffen, sobald im Tages-Snapshot über vier Wochen mindestens 5 % der Neunutzer eine Locale außerhalb von `de-*` haben, oder wenn ein zweiter Markt bewusst geöffnet wird. Dann entsteht ADR 0002 mit Bibliothek, String-Katalog und Übersetzungsprozess.
